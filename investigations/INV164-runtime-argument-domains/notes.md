# INV164 - runtime argument domains as `lint`-stage findings

Closes the buildable half of TODO #69.

## The gap

Four scripts that COMPILE and then die on their first bar, on which our
validator and TradingView's are both silent:

```pine
plot(ta.sma(close, 0))            // RE10001 "must be > 0"
plot(ta.sma(close, na))           // RE10003 "must not be na"
plot(ta.sma(close, 2000000))      // RE10004 "references too many historical candles"
plot(ta.pivothigh(high, -1, 2))   // RE10001 "'leftbars' ... must be >= 0"
```

Measured 2026-08-25 (the sweep this work inherited): `pine-lint` local and
`pine-lint --tv` both return clean on all four. That is the INV001 case in its
purest form and exactly the `lint` stage's charter.

## Oracle

The domains are NOT re-derivable by probing. RE-class errors surface only on
the chart legend overlay - never in the editor, never through either pine-lint
mode (G010). The oracle is therefore eight banner screenshots from the
2026-08-25 chart session, held in
`scripts/probes/re-class-runtime-errors/tv-banners/` as primary source, with
the per-line transcription in that directory's README.

Two properties of the banners make them unusually strong evidence: TV states
each domain **in the error text**, naming the argument ("Invalid value of the
'leftbars' argument (-1) in the 'pivothigh' function. It must be >= 0."), and
all four fire on bar 0, so the script never produces a single value.

## What landed

**The facts are data, not a table in the checker** (the Data-vs-Syntax rule).
`pine-data/raw/v6/runtime-domains.json` transcribes each banner as
`{function, parameter, min|max|notNa, code, probe, banner, quote}`; it lives in
`raw/` beside `required-params-probe.json` and survives scrapes for the same
reason - it is generated by fieldwork, not by the scraper. `generate.ts`
merges it into the affected parameter, tighter bound winning whichever source
it came from, and stamps two new schema fields:

- `rangeSource: "reference" | "runtime"` - the reference documents a range TV
  then happily runs outside of; a runtime bound is documented nowhere and is
  fatal. The checker picks its wording off this, because saying "documents"
  of a runtime bound sends the reader to a reference page that is silent.
- `notNa: true` - RE10003.

The consuming rule was already built (INV162's `ARGUMENT_OUT_OF_RANGE`), so
the numeric half needed no new check - only the wording split. The `na` half
is a new rule id, `ARGUMENT_NA_AT_RUNTIME`.

Output today (`pine-lint -H scripts/probes/re-class-runtime-errors/probe.pine`):

```
3:20: warning: [ARGUMENT_OUT_OF_RANGE] 'ta.sma' requires 'length' at least 1 at runtime, but 0 was passed. This compiles and then fails on bar 0 - the script never produces a value.
4:20: warning: [ARGUMENT_NA_AT_RUNTIME] 'ta.sma' rejects na for 'length' at runtime - this script compiles and then dies on bar 0. Nothing here is computed; pass a value, or guard the call.
6:26: warning: [ARGUMENT_OUT_OF_RANGE] 'ta.pivothigh' requires 'leftbars' at least 0 at runtime, but -1 was passed. This compiles and then fails on bar 0 - the script never produces a value.
```

## The overload bug this surfaced

`ta.pivothigh(high, -1, 2)` did not fire at first, and the reason is a defect
in INV162's rule that predates this work: it read arguments POSITIONALLY
against the MERGED parameter list. The merged list is overload #0's order
(`leftbars, rightbars, source`) while the call uses the other form
(`source, leftbars, rightbars`), so `high` landed on the bounded parameter and
`-1` on an unbounded one.

That is a missed finding here and a **false positive one signature away**,
which this channel cannot afford. `decidableParameters` now filters the
overloads to those the call could actually be - by positional arity and by
named arguments - and decides a position only where every surviving candidate
agrees on the parameter sitting there. An undecidable position is skipped, not
guessed. The corpus count for `ARGUMENT_OUT_OF_RANGE` was 0 before and after,
so the restriction removed nothing real.

## Deliberately not baked in

Recorded in the probe file's `_notAdded` block so removing an entry means new
evidence arrived, not that someone changed their mind:

- **RE10004's 5000-candle ceiling.** One banner from one script, and it is
  unestablished whether the limit is per-call, global, or interacts with
  `max_bars_back`. A `max: 5000` would flag every long-lookback call on an
  assumption. TODO #69's open question, still open.
- **`ta.pivotlow.leftbars`, and `length` on every other `ta.*` function.**
  These almost certainly hold. "Almost certainly" is what manufactured the
  retracted G002, and one chart capture per function is the price of each row.
  This is the whole coverage story of this rule today: **three facts**, and
  every extension needs chart fieldwork, which no probe or `--tv` call can
  substitute for.
- **`array.slice`'s inverted constant range (RE10044).** Banner captured, but
  it is a relation BETWEEN two arguments, which the per-parameter shape here
  cannot express. Needs a cross-parameter fact shape first - see TODO #69.

  pins all three cells plus the silent ones (both legal boundaries, an
  `input.int` length, and the un-baked 2000000 ceiling).

  a published script does not pass a literal `0` length - and the point of the
  gate is that a fire here would have been either a real find or a
  decidability bug.

  appearances. The `lint` stage carries no errors by construction.
